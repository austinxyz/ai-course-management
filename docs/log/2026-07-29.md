## student-management（归档为 2026-07-29-student-management）

第一条端到端垂直切片：学员名单只读查询，本地全链路跑通。

**做了什么：**
- 本地 Supabase（Docker，`supabase start`）+ `students` 表 migration + `seed.sql`（10 条虚构学员，CLI 本地专用不推生产）
- FastAPI（`uv` 管依赖）两个只读端点：`GET /api/students`、`GET /api/students/{email}`（大小写不敏感）
- `frontend/app/students/` 从纯前端 mock 改接真实数据：`page.tsx` 变成 Server Component 真 fetch，
  原来的交互逻辑整体搬进新的 `StudentsClient.tsx`（客户端组件不变）
- 顺带把之前已经做好但还没提交的 Next.js 设计系统脚手架（tokens、Button/Card/Badge/Input）一起提交了

**范围之外（故意不做）：** 编辑/归档/新增学员的持久化（UI 控件都在，但不接后端写接口）、
报课/作业/催作业数据、访问控制、部署。

**opsx 走了完整四阶段**：explore（中途按用户要求把 Scenario 手写规则改成"agent 起草 + 人工 review"）
→ propose → apply（3 个 task group，evaluator 打分 99 / 97 / 90，group 2 中途 BLOCK 过一次）→ archive。

**踩的坑（已记进 CLAUDE.md Pitfalls）：**
只读响应用 Pydantic `Literal` 校验没有 DB CHECK 约束的枚举列是隐患——一行脏数据能让整个列表接口
500。这个 change 里 `region`/`level`/`source` 本来就是应用层枚举（explore 阶段定的，DB 层特意不加约束
好留加值的口子），response schema 改用 `str` 才安全，`Literal` 留给以后的写接口用。

**其他技术小坑（没写进 CLAUDE.md，够不上"来自 evaluator retry"这条线，记这里备查）：**
- SQLAlchemy 对 `postgresql://` 默认找 `psycopg2`，装的是 `psycopg`(v3)，连接串要写成 `postgresql+psycopg://`
- Next.js 的 `server-only` 包在 vitest 下会无条件报错（它靠 Next 自己的 build pipeline 做条件替换，
  裸跑在 Vite/vitest 里没有这个机制）——改成注释约定，没用这个包

**验收标准全过：** 5/5 backend pytest，2/2 frontend vitest，`npm run build` 过，浏览器验证真实数据渲染正确、
未对齐微信徽章标红、控制台无报错。

## deployment（归档为 2026-07-29-deployment）

把上面那套本地栈搬上公网：https://ai-course-management.vercel.app/students

**做了什么：**
- Vercel（前端）+ Render 免费档（FastAPI）+ Supabase 云项目
- `.github/workflows/db-migrate.yml`：`push main` 自动 `supabase db push`，
  让 schema 跟代码一起上线，不依赖人记得手工推
- `error.tsx` / `loading.tsx` + fetch 15s 显式超时
- `DATABASE_URL` 归一化到 psycopg v3 驱动；后来又改成缺失即启动失败
- `render.yaml`、前后端各一份 `.env.example`

**范围之外（有意）：** 访问控制（单独 change）、保活、部署编排、staging 后端隔离。

**踩的坑（都进了 CLAUDE.md Pitfalls）：**

1. **`reset()` 不重新拉取数据。** 照 design 原本写的实现，"重试"按钮点了会原地不动。
   查 Next.js 16.2 文档才发现要用 `unstable_retry()`。这个错误恰好会在"后端刚醒过来"
   ——最需要重试生效的那一刻——失效。
2. **子目录 `.gitignore` 吃掉根目录的否定规则。** `create-next-app` 生成的 `frontend/.gitignore`
   里有 `.env*`，根目录的 `!.env.example` 管不到它，于是 `frontend/.env.example` 静默进不了仓库。
   group 3 的 evaluator 抓到的。
3. **localhost 兜底在云上是沉默的灾难。** 进程正常起、健康检查过，然后每个请求 500 说
   "连接 127.0.0.1 被拒绝"。改成缺失即抛错。

**部署时真实故障排查了一次：** 前端显示错误卡片。逐层探针定位——`/docs` 返回 200 说明
FastAPI 活着（顺带证明 `pip install uv` 在 Render 能跑通），`/api/students` 500 说明是查库炸的。
Render 日志给出真因：`relation "students" does not exist`。**连接完全正常，只是 migration 没推**——
GitHub Secrets 还没配，workflow 那次是失败的。我事先列的四种猜测（没配变量/IPv6/密码错/端口错）
一个都不对。日志比猜测可靠。

**最关键的一条验收（4.9）**：让 Render 空闲 17 分钟真正休眠，然后冷启动访问——
31 秒后页面渲染出**我们自己的错误卡片，而不是 Vercel 的 504**，点重试拿回数据。
这验证了 design 决策 #2 的核心假设：15 秒超时确实赶在平台函数上限之前触发。
如果不设这个超时，fetch 会挂到函数被平台杀掉，`error.tsx` 根本没机会渲染。

**evaluator 打分：** 97 / 99 / 81（阈值 80/70/80）。group 3 那条 81 里 evaluator 自相矛盾
（`status: RETRY` 但摘要报 PASS），已在归档的 eval-log.md 里补记说明。

**全过：** 11/11 backend pytest，9/9 frontend vitest，生产 `200 []`、详情 404、
Actions 连续三次 success。

## access-control（归档为 2026-07-29-access-control）

把系统从公网上关起来。之前页面、后端 API、`/docs`、`/openapi.json` 对任何人都是 200。

**做了什么：**
- `frontend/proxy.ts` —— 整站 HTTP Basic Auth（共享密码），matcher 负向排除静态资源
- 后端 FastAPI middleware 校验 `X-Backend-Secret`，`secrets.compare_digest` 常数时间比较
- `/docs`、`/openapi.json`、`/redoc` 默认关闭，仅 `ENABLE_API_DOCS` 显式设置才开
- `lib/api.ts` 在 server-side fetch 注入 secret
- 扩充 `openspec/config.yaml` 的 `NEXT_PUBLIC_` 泄露扫描

**范围之外（有意）：** 每人一身份、限流、登出、解除"禁止导真实数据"护栏。

**测试抓到两个 review 大概率看不出的问题：**

1. **中文 realm 让 401 变成 500。** `WWW-Authenticate: Basic realm="学员管理系统"` ——
   HTTP header 值是 ByteString，中文字符直接抛 `TypeError`。只有真正执行到 401 分支才会暴露。
2. **原有泄露检查对新变量全盲。** 人为植入 `NEXT_PUBLIC_BACKEND_SECRET`，旧规则一声不吭。
   扩充后双向验证：对现有代码无误报，且三种泄露形式都能捕获。

**fail-closed 做了真实的红绿验证。** 前后端的"缺变量时被拒"这两条断言，是在实现之后补的——
按 TDD 规则这只能算"测试了已有行为"。所以故意把实现改成错误写法
`if (configured && !matches)`，两边测试都如实报出 `200`：变量没设时整个互联网畅通无阻。
确认能抓住后才恢复。不这么做的话，这两条测试只是碰巧通过，证明不了任何事。

**踩了个假信号。** 验证本地后端时全部返回 200，一度看着像 middleware 完全没生效。
实际是上一轮的 uvicorn 还占着 8000，新进程绑定失败后静默退出，curl 打的是旧代码
（日志里 `[Errno 10048]` 才是真相）。这跟本 change 的核心风险同源——
**东西在跑，但不是你以为的那个**。后来验证前端时先主动重启了 dev server，就是因为刚吃过这个亏。

**evaluator 打分：** 100 / 99 / 93（阈值均 80），三组均一次通过。
group 3 那条 MEDIUM 采纳了：`.env.example` 里的 `ENABLE_API_DOCS=1` 改成注释状态，
这样即便有人把模板整段贴进平台环境变量，默认仍是"文档关闭"。

**生产验收（前后对比）：** `/students`、`/`、`/style-guide`、`/api/students`、`/docs`、
`/openapi.json`、`/redoc` —— 全部从 200 变成 401。未授权响应体 12 字节 `Unauthorized`，
拒绝发生在渲染之前。带正确凭据的路径由用户在浏览器实测确认（我不持有密码）。

**护栏未解除：** 认证虽已工作，但"不得导入真实学员数据"仍然有效，留待单独明确的决定。
