## nudge-advanced（归档为 2026-08-05-nudge-advanced）

`nudge` MVP 上线后跟最早的 Claude Design 导入稿对比，补上四处有意先砍掉的差距：多档文案模板、
导出名单、进度指示、已跳过人数展示。仍然不接真实发信通道。

**做了什么：**
- 三档固定文案模板（第一次提醒/第二次提醒/最后一次），按学员已催次数自动推荐默认档，手动切换
  只在草稿未编辑过时替换文本
- 导出未交名单 CSV（纯前端函数，用页面已加载数据，不发额外请求）
- 名单头部摘要"N 人未交 · 已跳过 M 人"
- 名单页头部 3 步进度指示（算名单→起草文案→标记/跳过）——**当天就被上线实测推翻，见下**

**opsx 走了完整四阶段**：explore → propose（4 组 task，四组评审 96/80、99/70、99/70）→ apply → 用户
直接测试后反馈两处体验问题，加了 group 4 修订（评审 99/80）→ archive。

**上线当天用户直接反馈两处，当场改：**
1. **已跳过的人从名单彻底消失，只剩个数字**——讲师确认不了跳过的是谁，也没法反悔。改为原地
   可见（灰显 +"已跳过"标签），加"取消跳过"入口。
2. **进度指示条永远卡在"起草文案"**——静态高亮给人"卡住了"的观感而不是进度，直接移除整块 UI。

**独立 code review 在 group-4 合入后立刻抓到两个真 bug（已记进 CLAUDE.md Pitfalls）：**
- 侧边栏徽标 `count_nudge` 判"跳过"用的是"曾经出现过 skipped 事件"，取消跳过后这个人被
  永久漏计——改成看最新一条 skipped/unskipped 事件。
- CSV 导出用了未过滤的 `people`（现在包含跳过的人），导出内容会混进已跳过的人，跟"导出内容
  与当前名单一致"这条 spec 矛盾——过滤掉 `skipped` 的行再导出。

**根因是同一类**：给一个只有"发生过"语义的判据加了撤销动作后，所有沿用旧判据的读取点都要
重新审计，不能默认它们还成立。

**其他技术小坑（没写进 CLAUDE.md，记这里备查）：**
PowerShell `Get-Content -Raw` + `Set-Content -Encoding utf8` 批量勾选 `tasks.md` 的 checkbox 时把
中文转成了乱码——已改用 Node 脚本做批量文本替换，并把该坑记进了 CLAUDE.md（这条够得上"来自
独立评审"，已写进正文）。

**验收标准**：backend 20+ 项 + frontend 24+ 项全绿（含 group-4 修订与 review 后的补丁），五组
evaluator 评审全部一次通过。
