## 浏览器验证：两次误诊，最后靠 Playwright 才走通

第一次尝试用内置 Browser pane 上传文件，卡死在没有弹窗也没有报错。诊断成
`document.hidden === true` 导致 React 推迟水合——**这个诊断是错的**，换真实
Playwright 浏览器后同样复现。真正原因是 `setInputFiles` 只要元素存在就成功，
**不等** React 装上 `onChange`；水合前设的文件被塞进 input 却没人在听，而重试
救不回来——**再选同一个文件不会再发 `change` 事件**，循环死锁。修法是每次
重试前先 `setInputFiles([])` 清空。

修完之后写了 9 项本地 e2e（`homework-import.spec.ts`），真选文件、真走
Server Action、真打后端，覆盖 UTF-8/GBK/传错文件/表头警告/幂等/17 行长清单不被
裁切。中途还抓到测试自己的两个假阳性：标记的是**跳过清单**里的人（不影响确认
条数，功能坏了这条也照样绿）；以及断言了错误的「将跳过」计数（漏算了讲师本人）。

## homework-auto-create-student：apply 两组，都一次过（99/80、100/70）

作业导入遇到不在学员表的邮箱，从"跳过、要求先手动建档"改成"自动建最小档案 +
一条 `derived` 报课，成绩正常写入"。`enrollment` spec 里 `derived` 这个来源值
此前只在一次性回填里出现过，这是它第一次成为常态触发路径。

- **group 1**（后端）：`_classify` 里对未知邮箱批量建 `Student`/`Enrollment`，
  `enrolled_at` 取该课程最早场次日期、无场次回退导入当天，只在真有未知邮箱时才
  查一次；`session.flush()` 补在 `Student` 与 `Enrollment` 之间——两者没有 ORM
  `relationship()`，unit of work 不会自动按外键排插入顺序，不 flush 会撞
  `ForeignKeyViolation`。返回体字段 `skipped_no_student` 直接改名 `auto_created`
  （不留双字段过渡，内部工具没有需要兼容的外部客户端）。34 项测试，含 7 个
  因改名/新行为而调整的既有用例。
- **group 2**（前端）：字段同步改名，「将跳过」计数整个移除（这类行不再是"跳过"），
  新面板复用既有 `normal` 语气而不是新造一个 `info` token——mock 稿画的是浅蓝，
  但仓库设计系统只有 danger/normal 两种，加第三种是范围外的事。29 项测试。
  VISUAL DIFF 那一步在这个环境里做不完整：站点的共享密码 Basic Auth 挡住了
  自动化浏览器（URL 内嵌凭据、预热 fetch 都不管用，导航请求不带上凭据缓存），
  改用 vitest 组件级渲染（真实渲染树，断言文案/tone/testid）替代，如实记录了
  这处降级，没有假装做了完整核对。

## 生产事故：作业导错课程，暴露"没有删除入口"

上线当晚讲师把 3 个新学员的作业误传到了 S3（应该是 S4）。查证用 `last-import` +
`source=derived` 过滤精确定位到 3 个人（第 4 个"同样是 derived"的报课其实是更早
一次回填留下的，`session_id` 不为空，判据是这个字段区分开的）。

报课记录能修：`enrollments` 有 DELETE + POST，删掉挂在 S3 下的三条、在 S4 下
重建，`enrolled_at` 沿用同一套"取最早场次日期"的逻辑保持一致。**成绩记录修不了**：
`homework_submissions` 唯一写入口是导入本身，没有任何编辑或删除接口——这是
`homework` spec 里明确写过的设计（写入以文件为准，两边都能改就会分叉），但没人
想过"导错课程"这种误操作场景。最后是直接连生产库删掉那三行。已经补进
`CLAUDE.md` 的 pitfalls 索引。
