# homework-upload Requirements

把作业成绩的导入从「本地命令行 + 本地文件」搬到网页上传，并把解析层挪进后端 ——
这样导入不再依赖某台机器上有那个文件。

## 为什么

`homework` 那一片把 `grades.csv` 的镜像做出来了，但导入只能这么走：

```
必须有 ai-course 仓库的 checkout
  → 必须在那台机器上
    → 必须记得命令行怎么写
      → 才能更新成绩
```

这是个 web app，却有一条能力只在一台电脑上存在。换台机器、或者你人不在电脑前，
成绩就更不了。

**我当初的论证是错的。** 我说「跨仓库数据先导入、不做运行时依赖，所以只能是本地 CLI」——
前半句对，后半句不成立。浏览器上传文件恰恰**就是**「先导入本系统数据库」，
完全不违反那条纪律。我把「后端读不到另一个仓库的文件系统」（真的）推成了
「因此必须是命令行」（不成立）。稿子里那个「重新同步 grades.csv」按钮是对的，
`.dc.html` 里我标成「永久偏离」的那一条要翻案。

## Goals

- 在作业页选一个 `grades.csv` 文件就能更新该课程的成绩，不需要本地有任何东西
- 写入前有一屏预览：会新建多少、更新多少、跳过谁、按什么编码读的
- 解析与校验**只有一处实现**，且在后端 —— 网页与将来的 MCP 打同一个接口
- 「不算作业的邮箱」成为可维护的数据，而不是命令行参数

## Non-Goals

- **MCP 服务器本身。** 将来批改 skill 会调 MCP 上传，但那是另一片。
  本片只保证接口的形状适合被它调用（见 Constraints）
- **学员导入 / 报课导入。** 只做作业一种。报课导入将来可能会有
  （EliteCoach101 的导出方式一旦明确），到时候再把入口加回去 —— 现在为它预留
  一个通用的「导入 / 同步」入口，就是拿一个不存在的能力占位
- **保存上传的 csv 原文。** 只记元信息（文件名、行数、时间、结果）
- **满分与分项条形图** —— 归 `homework-rubric`
- **改变认证模型。** 上传是写操作，而整站只有一层共享密码；这是**已知且接受**的风险，
  不是本片要解决的问题（见 Constraints）
- **导出。** 只进不出

## Constraints

### 接口是契约，网页只是它的第一个调用方

将来的 MCP 会直接打后端。因此：

- 解析、解码、校验、分类、排除 —— **全部**在 FastAPI 里。Server Action 只做
  「读文件 + 鉴权 + 转发」，**一行业务逻辑都不放**。放了的话 MCP 那条路会绕过它，
  两个客户端的行为会不一致，而不一致只在"命令行导进去的和网页导进去的不一样"时才暴露
- 返回体必须**自描述**：用了哪种编码、多少行、去重丢弃了哪些、将新建/将更新、
  两份跳过清单、表头是否与既有不符。MCP 那边没有人在看屏幕，只能靠返回值判断
- **课程既收 `course_id` 也收 `course_alias`，两者都给时 id 优先。**
  网页手里已经有 id（在 URL 里，选不错），而 MCP 手里只有一份刚批完的文件和
  "这是 S1"这个概念 —— 逼它先查一遍课程列表按名字匹配，等于把别名表的职责
  重写一遍在调用方。别名解析逻辑本来就存在，不是新代码。
  两者都没给则拒绝：**不从文件名推断**，源仓库的目录名已经错过一次

### 解析层从 `tools/` 挪进 `backend/app/`

`tools/homework-sync/parsing.py` 现在是纯函数，测试也在那儿。挪过去之后
`tools/homework-sync` **退休**（删除），测试一并搬进后端。

不保留 CLI：解析挪走之后它只剩「读文件 + 发上去」，而那件事网页已经能做。
两个入口就是两处错误态、两处校验要养。

### 架构纪律（既有）

浏览器 → Next.js → FastAPI → Postgres。浏览器不直连 FastAPI。
`tools/` 与将来的 MCP 是**服务端**客户端，直连 FastAPI 不违反这条 —— 这条管的是浏览器。

Server Action 必须自己调 `requireSitePassword()`：Server Function 编译成页面路由上的
一个 POST 端点，`proxy.ts` 覆盖页面加载**不构成**对它的保护（既有代码里已有这条注释）。

### 隐私

预览屏与导入记录都会显示真实学员的姓名与邮箱 —— 那是这个界面的用途，不可避免。
但：仓库不得提交任何真实数据（含夹具），测试一律虚构姓名 + `@example.com`；
排查用的探针脚本只打计数或邮箱前缀。

### 上传是写操作，而站点只有一层共享密码

现在页面只读，密码泄露的最坏情况是**被看到**。加了上传之后，拿到密码的人可以
**覆盖**成绩，而覆盖是静默的（幂等写入不会报错）。

这不改变 2026-07-29 的认证决策（不做每人一身份、不做限流），但要写在这里，
因为它是这一片**新增**的风险面，而不是一直就有的。缓解只有一条：源文件的权威副本
仍在 `ai-course` 仓库，重传即可修复 —— 除非覆盖发生在源文件也被改坏之后。

## Success Criteria

### 上传与预览

1. 在作业页选一个 `grades.csv`，看到预览：行数、去重丢弃的行、将新建 N 条、将更新 M 条、
   两份跳过清单（不在学员表 / 无报课记录），**且此时库里没有任何变化**
2. 预览里写明按哪种编码读的
3. 点确认后写入，并显示实际结果（新建/更新条数与两份清单）
4. 取消或离开页面，什么都没写

### 编码

5. UTF-8 的文件正常导入
6. GBK/GB18030 的文件也能正常导入，且预览里注明「按 GBK 读取」，中文可核对
7. 两种都解不开的文件被拒绝，给出可操作的错误，**不写入任何东西**

### 课程

8. 目标课程恒为当前选中的那一门，界面上无从选错
9. 上传的表头与该课程已有成绩的分项列不同时，预览给出**醒目警告**并说明两边分别是什么，
   但仍可确认 —— 评分表真的改了是合法情况

### 排除名单

10. 预览的每一行旁可标记「以后不算作业」，标记后该邮箱永久进入排除名单，**所有课程通用**
11. 标记之后**整屏预览重新计算**（不是只把那一行划掉）：将新建/将更新的数字、
    两份跳过清单都随之更新，确认时用的是重算后的结果。
    重算方式是拿同一份文件再发一次 `dry_run=true`，不在前端自行加减 ——
    前端算出来的数字与后端真跑时的判断可以不一致，而不一致只在写入后才暴露
12. 已在排除名单里的邮箱，在后续任何一次导入中都不会写入，且在预览里显示为已排除

### 接口

13. `POST /api/homework/import` 带 `dry_run=true` 时不写入任何东西，返回与真跑相同的判断
13b. 该接口接受 `course_id` 或 `course_alias`；两者都给时以 id 为准，都不给则拒绝
14. 同一份文件重复导入不产生新记录（沿用既有的幂等语义）
15. 该接口不依赖任何 Next.js 特有的东西，可被服务端脚本直接调用

### 清理

16. `tools/homework-sync/` 已删除，其测试搬进后端且仍然通过
17. 侧边栏那一项改为**「作业 CSV 导入」**并真的跳到作业页 —— 标签写实际能做的事，
    不写一个暗示通用导入面的名字
18. 学员页的「导入 CSV」按钮与新建弹窗里的「批量导入请用 CSV 导入」链接**删除**：
    它们背后没有任何功能。按不动的按钮比没有按钮更糟——它看起来像功能坏了

### 生产验收

19. 从浏览器上传 `session1/grades.csv`，预览显示「将更新 16 条」（不是新建 —— 已经导过一次）
20. 确认后计数不变，说明幂等
21. 上传一份故意存成 GBK 的副本，中文在预览里正确显示

## User Stories

- 作为讲师，我批完作业后想直接在网页上传成绩，不用回到那台有仓库的电脑
- 作为讲师，我想在写入之前看清楚会发生什么 —— 尤其是"谁会被跳过"
- 作为讲师，我不想每次都记得排除自己的测试提交；标记一次就该永久生效
- 作为讲师，将来我想让批改 skill 改完直接调 MCP 上传，中间不经过我

## 已定的判断（起草时不确定，2026-07-31 与用户确认）

1. **标记「以后不算作业」之后整屏重算**，重算方式是拿同一份文件重发一次 `dry_run=true`。
   前端自行加减会得出一个后端并不认同的数字，而不一致只在写入后才暴露。
   代价是"标记"变成一次真写入 + 一次重新预览，界面在这期间进入 busy 态。

2. **侧边栏那一项改为「作业 CSV 导入」并跳到作业页；学员页那两个死键删除。**
   通用的「导入 / 同步」标签本身就是个小谎——它暗示一个不存在的通用导入面。
   报课导入将来可能会有，到时候再加回入口，不现在占位。

3. **大小上限 1MB，类型只按内容判断，不看扩展名。**
   真实文件最大 18 行 / 几 KB。扩展名是最容易伪装也最容易误伤的判据；
   能不能解析出必需的表头才是真判据。

4. **导入记录存下来，并在作业页显示一行「上次导入 …」**（时间 · 文件名 · 行数）。
   稿子有这一行。不存原文，只存元信息。

5. **表头缺列的错误信息要说人话。** 现在的 `BadHeader` 是给命令行看的
   （"表头缺少必需的列：邮件"）。网页上要能让人一眼知道"你可能传错文件了"，
   而不是去猜哪一列叫什么。

## 已知会踩的坑（来自 CLAUDE.md，实现时对照）

- **Server Action 抛出的错误在生产构建里信息会被抹掉** —— 预期内的结果（编码不对、
  表头不符、课程不存在）必须用**返回值**表达，不能抛异常再在客户端匹配 message
- **写入失败的信息必须渲染在触发它的那块界面上，而承载它的界面不能先消失** ——
  预览屏在写入期间要禁用所有出口（含取消），只在成功回调里关闭
- **测试要用挂住不 resolve 的 promise 断言 disabled** —— 只断言最终态的测试对这类回归全盲
- **清表 fixture 要跟着外键长** —— 新增排除名单表与导入记录表后，回头改那张清空顺序表
- **`vi.clearAllMocks()` 清调用记录但不清实现** —— 用例内显式设定自己依赖的返回值
- **jsdom 没有布局** —— 预览屏若有长列表，裁切缺陷只能在真实浏览器里用足量数据验
