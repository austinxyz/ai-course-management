## Goals

- 详情面板新增"发送邮件"按钮（第三个按钮，与"复制文案"/"标记已催"并列），点击后弹确认对话框（"确认发送给 {邮箱}？"），确认后真正通过 SMTP 把当前草稿发到该学员邮箱。
- 发信人固定为讲师本人专用账号 `austin.aicourse@gmail.com`（Gmail 应用专用密码鉴权），不做多用户/多发信账号支持。
- 邮件主题固定格式 `《{课程名}》作业提醒`，三档模板共用同一主题格式，不随档位变化。
- 发送成功后自动记一条 `nudged` 事件（`channel=email`），不需要讲师再手动点"标记已催"。
- 发送失败时（SMTP 报错、超时、鉴权失败等）界面就地报错，不记录任何事件，讲师可以重试或退回手动复制发送。

## Non-Goals

- 不做多发信账号/多讲师支持——固定一个 Gmail 账号。
- 不接 Gmail OAuth——用 SMTP + 应用专用密码，理由：只有一个人用，OAuth 的"多用户各自授权"价值在这里体现不出来，换来的是不必要的 Google Cloud 项目搭建、同意屏幕审核、refresh token 管理成本。
- 不做批量发送——沿用 nudge 已定的"按人逐条操作"。
- 不改变"微信已对齐走微信"这条历史判断在**手动**"标记已催"路径上的含义；"发送邮件"是独立的新动作，不管微信是否对齐，始终走邮箱。
- 不做发信频率限制/配额管理——单人使用量级远低于 Gmail 每日发信上限，不构成本轮范围内的风险。
- 不做邮件模板的富文本/HTML——纯文本邮件，与草稿 `textarea` 内容所见即所得。

## Constraints

- SMTP 凭证（账号、应用专用密码）只走环境变量，不入库、不出现在前端代码里——沿用 `CLAUDE.md` 既有的密钥管理纪律。
- 测试中必须验证不会真实发信（`CLAUDE.md` 硬性要求）——SMTP 调用点要能在测试里完全 mock 掉，不依赖网络。
- 涉及外部依赖（SMTP 服务器）的路径必须有超时与异常路径的测试。
- 邮件正文就是详情面板当前草稿的原文（含讲师手动编辑的内容），不做额外包装或签名追加。
- "发送邮件"按钮不影响"复制文案"/"标记已催"/"跳过"三个既有按钮的行为，四者并存，讲师按自己的习惯选路径。
- 发送成功后记录的 `channel` SHALL 固定为 `email`，不经过既有 `_channel_for()`（按微信是否对齐自动判定）那条路径——否则一个微信已对齐的学员走"发送邮件"按钮发出去的邮件，历史记录会显示成"微信"，跟实际发生的事不符。`POST /api/nudge/events` 现状不接受调用方指定 `channel`，本变更要么加一条不经过 `_channel_for` 的记录路径，要么在 design 阶段给出等价方案。

## Success Criteria

- 点击"发送邮件"，出现确认对话框显示目标邮箱；确认后邮件通过 `austin.aicourse@gmail.com` 真实发出，主题为 `《课程名》作业提醒`，正文为当前草稿原文。
- 发送成功后，详情面板的催促历史立刻多一条"已催 · 邮件"记录，不需要额外点击。
- 断开网络或给一个错的应用密码模拟失败，界面显示明确错误信息，历史记录不新增任何条目。
- 取消确认对话框，不发送、不记录，回到详情面板原状态。

## User Stories

- 我想直接把系统生成的提醒文案发出去，不想再复制粘贴到 Gmail 网页里手动发一遍。
- 我担心手滑点错人发错邮件，希望发送前有个"确认发给谁"的提示。
- 发信失败了我想知道，而不是系统悄悄记了"已催"但学员根本没收到。
