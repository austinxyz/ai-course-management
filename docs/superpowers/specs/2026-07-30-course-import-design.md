# 从 course-portal 导入四门课程

## 为什么

生产库里现在有一门课，是我在 `course-catalog` 生产验收时建的 ——
**结构真实、内容我编的**（课程名 `Claude 实战入门 · S1`、定位与作业题目都是我按设计稿 placeholder 填的、
两场日期是我为验夏令时挑的 10-15 / 12-15）。验收标准写的是"建一门真实课程"，
我手上没有真实值就自己填了，这一步做得不对。

真实课程在 [course-portal](https://austinxyz.github.io/course-portal/)：S1–S4 四门，
每门都有课名、英文名、定位、介绍、课时、作业、上课时间、状态。

## 前置

**必须先完成 `course-scheduling-fields` change**，否则：
- 150 分钟的课时没处放（`hours` 只收 1–4 的整小时）
- 8:30 PM ET 的场次只能先手算成美西时间再录

## 字段映射

| 门户 | 系统 | 说明 |
|---|---|---|
| 课程名 | `name` | |
| SESSION N 的 `SN` | `short` + 一条别名 | 简称给人看，别名给导入匹配 |
| 英文名 | **一条别名** | 不塞进介绍。EliteCoach101 里很可能就写英文名，放别名里是真的能匹配上 |
| 课程定位 | `tagline` | 原文 |
| 课程介绍 | `intro` | 原文 |
| 课时 150 分钟 | `duration_minutes = 150` | 需要前置 change |
| 作业 | `homework_title` | 原文 |
| — | `default_tz = America/New_York` | 四门课都排在 ET |
| 上课时间 | 一条 `course_sessions` | `local_date` + `local_time 20:30` + `tz America/New_York` |
| — | 场次 `teacher = "Austin Xu"` | 门户上没有讲师字段；讲师本人指定统一填这个值，之后逐场改 |
| 状态（已结束/开放报名） | **不映射** | 状态由场次日期派生（`pending`/`done`），不是课程上的字段 |

**年份按 2026 填**。据此 S1–S3 与 S4 的 7/26 都会自动是「已上」，7/31 那场「待上」。

**中文课名不进别名** —— 不确定 EliteCoach101 里用不用中文全名。以后随时能加，
加错了反而要 delete + insert（别名主键是归一化值，不能 update）。

## 执行

一次性脚本，位于 `tools/course-import/`，含 `courses.json`（门户上的公开课程信息，
**不含任何学员数据**，可提交、可 review、可重跑）。

```
1. dry-run —— 打印每门课是「新建」还是「更新既有」、各挂哪几场，不写任何数据
2. 人工核对（讲师最担心的就是"哪门课挂到哪几场"错位）
3. 实跑
```

**匹配靠别名，不靠课程名。** 脚本按 `courses.json` 里每门课的别名去查现有课程：
命中就**更新那门课**，没命中才新建。直接后果 —— 生产上那条假记录握着别名 `S1`，
会被就地改造成真的 S1，**不需要删除课程**（课程本来就没有删除入口，
它是报课/作业/催作业共用的口径）。

**脚本不删场次。** 生产上那两场假的（10-15、12-15）由人在界面上删 ——
删除是决定，不交给批处理。脚本只把"库里有、导入清单里没有"的场次列出来提示。

**场次去重按 (日期, 时间, 时区)**，重跑不会把同一场加两遍。

凭据（`BACKEND_URL`、`BACKEND_SECRET`）运行时由讲师从自己的 shell 提供。

## 验证

1. 对生产跑 dry-run，逐行核对「课程 → 场次」的对应关系
2. 实跑
3. 界面上确认：四门课都在；S1 的名称已从假值变成真值；别名各两条；
   S4 有两场且 7/31 是「待上」
4. 抽查 **7/31 那场**的时区行：美东 20:30 → 美西 17:30 同日、上海 08:30 次日。
   拿 7 月的场次核对是有意的——它在夏令时内；若拿 12 月的场次比，上海应是 09:30 次日，
   两个值都对，但混着看会以为哪里错了
5. 手工删掉 S1 那两场假场次

## 验收标准

- 生产课程数 1 → 4（那条假记录变成 S1，不新增）
- 每门课两条别名（`SN` + 英文名），共 8 条
- 场次共 5 场，讲师均为 `Austin Xu`，时区均为 `America/New_York`
- 时长均为 150 分钟
- 重跑脚本不产生任何重复课程或重复场次

## 遗留

- **S1、S2 更早那几期未导** —— 门户上没有，讲师会手工补录。
  补录后它们会按日期插到 6/28 之前，「第 N 场」自动重排（这是期望行为，见
  `course-scheduling-fields` requirements 的 Non-Goals）
- 价格与组合价不进系统
- 讲师统一填 `Austin Xu`，若某场另有讲师需人工改
- 门户是静态 HTML，本次是**人工转录**成 `courses.json`，不做抓取解析 ——
  四门课，写解析器的成本高于收益，而且解析器会在门户改版时静默失效
