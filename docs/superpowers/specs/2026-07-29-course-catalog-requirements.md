# course-catalog Requirements

来源：claude.ai/design 项目「讲武堂学员管理系统」课程页改版（2026-07-29 重新导入，
设计基准存于 [docs/superpowers/specs/mocks/2026-07-29-course-enrollment-design.dc.html](mocks/2026-07-29-course-enrollment-design.dc.html)）。
对应 [docs/requirements.md](../../requirements.md) §4.2 报课的前置：报课要按平台别名匹配到课程、
挂到具体场次，课程与场次不存在的话报课记录无处可挂。

## Goals

- **课程可维护**：新建/编辑课程 —— 课程名、简称、一句话定位、课程介绍、每场时长、
  作业题目、平台别名、上架状态
- **场次可排**：一门课下挂多场，**每场独立讲师与学员**。场次有日期、时间、讲师、状态、备注
- **跨时区显示正确**：时间按美西记录，页面同时给出各时区对应时间。
  夏令时切换不得让已排场次的显示时间集体偏移
- **平台别名是导入的匹配入口**：同一门课在平台里的多种写法（`S1`、`Session 1`、`第一期`…）
  都能匹配到本课程。`grades.csv` 现用的 `S1`/`S2` 属于别名，不是课程身份
- 侧栏新增 `课程` 导航项（现 `NavKey` 无此项）

## Non-Goals

- **不做报课** —— 报课表、导入中间格式、手工补录都属下一个 change。
  直接后果：场次卡片上设计里那个「已报 N 人」**本 change 不显示**（不是显示 0 —— 显示 0 会
  被读成「这场没人报」，而真实含义是「报课功能还没有」）
- **不做作业评分** —— 课程上只存「作业题目」这一条元数据。
  评分维度仍不落成列（CLAUDE.md：各课评分项无交集，新增课程不得改表结构）
- **不做课程删除** —— 设计里课程只有「上架 / 已下线」，没有删除入口。
  已下线课程不出现在新报课的选项里，但历史报课与作业记录不受影响
- **不做讲师实体** —— 讲师是场次上的字符串，可选项从已有场次去重得出。
  代价：改名会造出两个"人"。讲师就讲师本人与合作伙伴几个，可控
- **不做批量排课**（如"每周三连开 6 场"）—— 一场一场加
- **不做课程与学员的直接关联** —— 那是报课的事

## Constraints

- 架构纪律不变：浏览器只与 Next.js 通信；写操作走 Server Actions；只有 FastAPI 访问数据库；
  migration 只进 `supabase/migrations/*.sql`
- **场次时间存「美西本地日期 + 本地时间 + IANA 时区名」**，不存固定 UTC 偏移。
  讲师排课时想的是"美西晚 7:30"，这个值在夏令时切换前后都不该变；"美东几点"是派生的。
  存固定 `-8` 会让 11 月第一个周日之后所有场次错一小时，**且错的方向对每个时区不同**
  （美东与美西同日切换、亚洲根本不切换）。换算在展示层用 IANA 时区名做，Postgres 与浏览器都自带库
- **场次状态是"派生 + 可覆盖"**：默认按日期自动判断（待上 / 已上），
  人工可覆盖为 已取消 或修正，并且能「恢复跟随日期」。
  因此需要一个可为空的覆盖字段——只存一个 `state` 列表达不了"跟随日期"这个状态
- **平台别名在全局唯一**：同一别名不得同时指向两门课，否则导入时无从判断。
  这是我起草时定的（设计未明说），理由是别名的唯一用途就是消除歧义
- 课程名改动**不自动改别名**。设计明写「课程名改了要同步平台别名，否则下次导入会匹配不上」——
  界面要给出这个提示，但不替用户改
- **已有报课不因课程信息改动而变动**（设计原文）。本 change 没有报课表，
  但课程字段的可变性设计要为此留好：报课记录将引用 `course_id` 而非课程名
- 时长（每场）取 1–4 小时；简称可空，空则显示 `—`
- **别名匹配与唯一性都按"去空白 + 转小写"判定**（`S1`、`s1`、` S1 ` 视为同一别名）。
  与邮箱统一转小写同源：平台导出的写法不受我们控制，把归一化放在边界上才便宜
- **课程名不要求唯一** —— 匹配靠别名，课程名是给人看的。两门同名课是讲师自己的事
- **状态的自动判断以美西日期为准**（`America/Los_Angeles` 的今天），
  不是服务器所在时区的今天。否则同一场课在 UTC 已跨日、美西还没到，状态会提前翻成 `done`
- **场次状态在库里存英文 key**（`pending` / `done` / `cancelled`），中文由界面映射。
  这与现有 `region`/`level`/`source` 存中文不一致，是**有意的**：那三个字段的取值是业务词汇
  （`美东`、`小白`、`讲武堂`），改文案就是改业务含义；场次状态是状态机，
  中文当 key 会让"把『已上』改叫『已完成』"变成一次数据迁移。
  不回头改那三个字段——它们已有生产数据，为一致性做迁移不值得。
  新写的枚举列从这里开始用英文 key

## Success Criteria

1. 能新建课程：填课程名即可保存，其余字段可后补；简称留空显示 `—`
2. 能编辑课程全部字段；保存后刷新仍在
3. 编辑课程名时界面提示「课程名改了要同步平台别名」；别名本身不被自动修改
4. 能给课程添加别名、删除别名；添加一个已属于**另一门课**的别名被拒绝并说明原因
5. 能给课程添加场次：日期 + 时间（美西）+ 讲师 必填，备注可空
6. 场次列表按日期排序，每场显示序号、日期时间、讲师、状态、备注
7. 场次卡片给出各时区对应时间。**验夏令时必须拿亚洲行比，不能拿美东行比**：
   美国两地同日切换，PT↔ET 恒为 3 小时，这条断言怎么写都会通过；
   而中国不用夏令时，PT↔上海在 **15 与 16 小时**之间跳。
   因此测试取 10 月与 12 月各一场同为"美西 19:30"的场次，
   断言上海行分别为次日 10:30 与 11:30。这条要有自动化测试，不靠肉眼
8. 场次状态默认按日期自动判断（`pending` / `done`）；手动改为「已取消」（`cancelled`）后显示为手动覆盖，
   点「恢复跟随日期」回到自动
9. 能修改与删除场次；修改一场已经上过的场次时，界面先给出警示文案
10. 讲师选项来自已有场次去重；能当场新增讲师名并用于本场
11. 课程可切换「上架 / 已下线」，已下线在列表上有可见标记
12. 没有场次的课程显示「还没有排课」，并说明排课后才会出现在报课的场次选项里
13. 侧栏 `课程` 可进入该页；`报课` 仍是占位页（本 change 不做）
14. 前后端测试套件无回归；`supabase db reset` 后 migration 可重放

**生产验收**：生产库有真实学员数据，但课程与场次是新表、无历史数据，因此可直接建真实课程。

15. 在生产建一门真实课程（S1 或当期课程）+ 至少两场（其中一场在 11 月之后，
    用于验证夏令时），刷新确认落库
16. 别名填入 `S1`（`grades.csv` 现用写法），为下一个 change 的导入匹配做准备

## User Stories

- 作为讲师，我想把课建到系统里：名称、一句话定位、招生用的完整介绍、这次的作业题目，
  这样报课与作业都有地方挂
- 作为讲师，我想给一门课排多场，每场单独选讲师 —— 报满后加的第二场、为亚洲时区加的晚场，
  讲师可能都不是同一个人
- 作为讲师，我按美西时间排课，但学员分布在美东、加拿大与亚洲；我想在页面上直接看到各时区对应时间，
  不用自己算，**也不想在夏令时切换后发现所有时间都错了一小时**
- 作为讲师，我想登记平台里这门课的各种写法，这样下次导入报课数据时不用手工对
- 作为合作伙伴，我想看到哪门课已下线、哪场已取消，不必去问

## 待 review 确认（我起草时自行判断，可推翻）

- **别名全局唯一**（见 Constraints）。也可以放宽成"同一门课内唯一"，
  但那样导入遇到歧义别名时只能报错让人处理，等于把问题推给运行时
- **场次删除是硬删除**。本 change 没有报课，删掉没有连带影响；
  但报课 change 必须补一条：**删除已有报课的场次要被拒绝**，否则报课记录会指向不存在的场次。
  这条我会写进本 change 的 Non-Goals 备注，作为下一个 change 的输入
- **课程主键用独立 id**（设计脚本即如此），简称与课程名都可改。
  不用简称当主键的理由：设计允许简称留空且可改，而 `grades.csv` 的 `S1` 走别名匹配
- **「每场时长」放在课程上**（设计里是"默认上课设置"），场次不单独覆盖时长。
  若将来某场要加长，需要再开字段

## Design System

沿用既有实现（`frontend/app/globals.css` 的 token，`frontend/components/ui/`）。
设计基准就是导入的 `.dc.html`，其中课程页与课程弹窗用到的组件（Button primary/secondary/ghost、
Badge muted/danger/success、Card / CardHeader / CardTitle / CardDescription、Input）本地全部已有，
**不需要改组件层**。

`HAS_UI_SURFACE: yes` —— 本 change 有大量新界面（课程页、场次行内编辑、新增场次表单、
新建/编辑课程弹窗）。**不另画 mock**：导入的 `.dc.html` 就是设计产出物本身，
二次绘制只会产出一份权威性更低的副本。

propose 阶段的 mocks 产物（`docs/superpowers/specs/mocks/2026-07-29-course-catalog-mocks.html`）
写成一页**导览**：列出课程页与课程弹窗各在 `.dc.html` 的哪个 `sc-if` 分支、
逐块列出要照抄的 verbatim 文案（如「还没有排课。加一个上课时间后…」、
「课程名改了要同步平台别名」、「这一场已经上过，改动会影响历史记录和作业统计…」）、
以及 token 用法。apply 阶段的 MOCK 任务读这一页，VISUAL DIFF 对着 `.dc.html` 本体比。
这样既不重复 160KB，也不让 mocks 产物退化成空壳。

## Referenced Capabilities

- ADD `course-catalog` —— 课程与场次的读写契约：课程 CRUD（无删除，只有上下架）、
  别名增删与全局唯一、场次 CRUD、场次状态的派生与覆盖、跨时区时间换算的正确性要求
- 不改 `student-roster`。课程与学员在本 change 里没有关联（关联发生在报课）
