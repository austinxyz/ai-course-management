homework — 视觉基准导览

视觉基准是 docs/superpowers/specs/mocks/2026-07-31-course-enrollment-design.dc.html 的 sc-if isHomework 分支。这份导览讲的是哪些照做、哪些有意不做， 以及为什么。稿子是单向的（实现的改动不会 sync 回去），所以 「不做」的那些条目要一并抄进 .dc.html 的头注释「已知偏离」清单。

照做

  • 左表右详情，与学员页同一骨架
  • 顶部课程 chips，每个带该课的未交数
  • 状态用小圆点 + 文字，四种颜色（见下）
  • 分段筛选「全部 / 已交 / 未交 / 待回复」，各带计数
  • 表格列：学员 · 提交时间 · 总分 · 分项 · 回复
  • 未交那一行整行浅红底（#fdf9f8），选中行左侧 2px 主色竖条
  • 详情里的分项按 zebra 斑马纹逐行列出
  • 页脚显示来源：session1/grades.csv · 第 7 行
  • 色板全部沿用既有 token，不新增

有意不做（连同理由，抄进 .dc.html 的「已知偏离」）

稿子上的不做的理由
「重新同步 grades.csv」按钮 grades.csv 在另一个仓库，Render 上的后端看不到那些文件。 同步只能是本地 CLI。按钮做出来只会是个骗人的死键。
分项条形图、11 / 15、按比例的颜色分档 各项满分不在 csv 里，在 rubric.md 里 （而那两份还是错位的）。只显示原始分。
「第 2 次提交 · +6 分」历史版本 纯镜像整行覆盖，不留旧版。要留就得多一张表，而重交这件事目前只发生过一次。
「截止后交 / 按时交」 courses 上没有「作业截止日期」这一列。截止日期对 §4.4 催作业更有用 （「已过 N 天」），跟着那个 change 一起加。
页首「催未交的人」按钮 §4.4，本次范围外。
回复状态的三个可点分段（已回复 / 草稿待发 / 未回复） 页面全只读。而且稿子这三个词与 csv 里的实测值 （待回复、草稿已创建）根本不是一套。原样显示 csv 的值。
总分现算（稿子是 sumOf(g)） session2 有 1 行「总分 ≠ 分项之和」。现算会与源文件悄悄不一致， 而这一页的全部价值就是忠实反映源文件。存 csv 里那个数。
三态（已交 / 未交 / 未开放） 改成四态，多一个「未定场次」。倒推进来的报课全是未定场次， 没有场次就没有截止时间，催他是冤的。
「未开放」按课程整体算（稿子的 opened 布尔） 改成按学员自己那一场。S1 已开过几场、又排了一场未来的， 课程级口径会把报了未来那场的人推进未交名单。

两份清单必须分开列 —— 处置相反：上面那份要先建学员，下面那份要补报课。 混在一起就变成一句无从下手的「有 3 个人有问题」。
输出全中文，必须走 sys.stdout.buffer.write(...encode("utf-8"))： Windows 控制台默认 cp1252，第一行就会抛 UnicodeEncodeError， 而 pytest 捕获的是内存流，本地测试全绿也照样炸。

移动端

桌面单一视口，没有移动版 —— 与既有各页一致，这是既定的范围限定 （内部工具，讲师在电脑上用）。名单沿用学员页那套表格骨架，窄屏表现与它相同， 不为本页单独做响应式。

会踩的坑（本页专属）

表格外框的 overflow-hidden。 为圆角加的 overflow-hidden 配上会被压缩的 flex 子项，会把超出的行 裁掉，而外层滚动容器因此看不到任何溢出 —— 哪儿都没有滚动条。 S1 有 17 行，够撞上（报课页是 22 条时暴露的，4 条时看着好好的）。 外框要 flex-none。jsdom 没有布局，单测量不出来， 必须在真实浏览器里用 S1 的全量数据验一次。
