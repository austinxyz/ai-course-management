course-scheduling-fields — 视觉基准导览

界面基准仍是 docs/superpowers/specs/mocks/2026-07-29-course-enrollment-design.dc.html 的 sc-if isCourses 与 showCourse 两个分支（在线版 claude.ai/design/p/1d976911-7272-4c83-aa54-715d22105341）。 本页只讲**这次要改的两处**，以及为什么它们**有意偏离**那份设计稿。

这次的根因，写在最前面：上一轮我把设计稿里的示例值当成了真实约束 —— 稿子里画了 1/2/3/4 小时四个 chip，我就把列做成了 hours int 且限制 1–4； 稿子里写着「时间（美西）」，我就把美西写死进了 schema 默认值和换算基准。 真实课程是 150 分钟、8:30 PM 美东，两个都存不下。 实现这两处时不要再照稿子抄回去。

时区 chip 的来源

chip 列表直接用 frontend/lib/tz.ts 的 ZONE_ROWS —— 与场次卡片下方那几行换算用的是同一个数组。不要另建一份清单： 两份会漂移，而漂移的样子很难看 —— 用户选了一个时区，那个时区却不出现在换算行里。

API 不受此限：TimezoneName 校验器收任意 IANA 名（导入脚本要用）。 界面是便利，API 是契约。

期望输出（正确性要求，不是视觉决定）

场次（录入值）美西行上海行
2026-07-31 美东 20:3017:30 同日08:30 次日
2026-10-15 美西 19:30—（基准行）10:30 次日
2026-12-15 美西 19:30—（基准行）11:30 次日

日期必须写死在断言里。同样是美东 20:30，12 月那场的上海行是 09:30 次日 —— 美国退出夏令时、中国不用。不锁日期的断言会在换季后自己变红。

视口范围

与 course-catalog 相同：桌面单一视口，没有移动版。 使用者是讲师与合作伙伴两人，都在电脑上用。这是范围限定，不是遗漏。
