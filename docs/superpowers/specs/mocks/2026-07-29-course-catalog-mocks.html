Token 用法

  • 组件全部取自 frontend/components/ui/：Button（primary / secondary / ghost，size sm）、 Badge（muted / danger / success）、Card 家族、Input。不新增组件。
  • 颜色只用 frontend/app/globals.css 的 token：面板 bg-surface、 次级块 bg-surface-muted、描边 border-border、 主色 text-primary、警示 text-danger / border-danger-border。 设计里出现的 #9c3417 等十六进制值是 token 的当前取值，实现里不要写死。
  • 状态 Badge 的 variant 映射：pending → success、done → muted、 cancelled → danger（取自设计脚本 s.stateVariant）。 注意「待上」是 success 而非 default —— 这是设计的选择，别改成灰色。
  • 等宽字体（font-mono）用于日期、时间、时区行与别名；正文用 font-sans。
  • 行内编辑沿用学员详情面板既有那套：回车保存 · Esc 取消， 保存中降低不透明度，失败就近显示并保留用户输入。

时区行的期望输出（这不是视觉决定，是正确性要求）

场次卡片第二行列各时区对应时间。验收必须拿亚洲时区比，不能拿美东比： 美国两地同日切换夏令时，美西→美东恒为 +3 小时，那条断言无论换算实现对错都会通过。

场次（美西墙上时间）美东上海
2026-10-15 19:3022:30 同日10:30 次日（+15h）
2026-12-15 19:3022:30 同日11:30 次日（+16h）

两场的美西显示值都必须是 19:30 —— 这是"存墙上时间"的意义所在。

视口范围

桌面单一视口，没有移动版。 设计里侧栏固定 216px、详情面板固定 358px、 容器 min-height:640px 且横向不折行 —— 它是为笔记本屏幕画的。 使用者是讲师与合作伙伴两人，都在电脑上用（CLAUDE.md：不面向学员）。 因此本 change 不产出移动版布局，也不为窄屏做断点； 这是有意的范围限定，不是遗漏。将来若真要手机上查名单，那是独立的一件事。
