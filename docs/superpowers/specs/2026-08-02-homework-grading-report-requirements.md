# homework-grading-report Requirements

作业详情面板加一个入口，讲师能把批改工具产出的逐分项详细报告（`{姓名}_{日期}_report.md`）
上传进系统，解析出每个分项的评语、整体亮点、改进建议，覆盖到当前选中学员的这条提交上。

## 为什么

`ai-course/tools/homework-grader/session*/submissions/` 下每份提交都有一份详细报告，
里面是逐维度的评语（不只是分数）——这些内容目前只存在于另一个仓库的 md 文件里，
讲师要看只能去翻源仓库。`grades.csv` 导入进来的 `highlight`/`improve` 是精简版，
report.md 里的内容更细致（按分项拆开），值得让讲师在系统里直接看到。

## Goals

- 详情面板新增一个按钮，讲师为**当前选中的学员**弹出文件选择框，选一个 `.md` 文件
  （不做批量/文件夹导入，不做文件名到学员的自动匹配——上传时系统已经知道是哪条提交）
- 上传后先进入**预览屏**：展示解析出的逐分项评语、亮点、改进建议；如果解析出的
  分项得分或总分与该提交已有的 `scores`/`total` 不一致，该分项行**高亮警告**，
  但不阻止确认导入（讲师自己判断要不要处理这个不一致）
- 预览屏的**每一条分项评语前有一个勾选框**，默认全部勾选（含得分不一致的项——
  警告只是提示，不代表默认不要）；讲师可以取消勾选某几项，确认导入时只写入
  勾选了的那些分项评语，不影响其余分项。亮点/改进建议**不单独勾选**，是否覆盖
  跟在整体的"确认导入"动作上——确认了就一起覆盖，没有单独跳过的入口
- 确认后写入：解析出的亮点/改进建议 SHALL 覆盖该提交当前的 `highlight`/`improve`；
  逐分项评语存成新数据，供详情面板展示
- 分项对齐 SHALL 只取编号前缀（如 `A1`）匹配，忽略后面的中文标题文字——
  report.md 表格写的是「A1 工作流结构」（有空格），`scores` 里存的 item 键是
  「A1工作流结构」（无空格），只比编号避免格式差异导致匹配不上
- 一旦某条提交的 `highlight`/`improve` 来自 report 导入，之后**重新导入这门课的
  grades.csv SHALL NOT 覆盖**这两个字段——grades.csv 那份是精简版，不该冲掉更细致
  的版本。没被 report 覆盖过的提交不受影响，grades.csv 重新导入照常更新它们

## Non-Goals

- 不解析、不存「讲师回复草稿」段落——那是要发给学员的文字草稿，跟已经上线的
  `replied`/`replied_at` 手动标记是两回事，不在这次范围内
- 不解析、不存「作业原文」段落（学员的提交内容本身）
- 不做批量导入一个 session 目录下所有 report.md 的入口
- 不做文件名到学员/提交的自动匹配（按姓名+日期猜）——上传都在选中提交的详情面板里做，
  已经知道是哪条
- 不追溯修改历史——report 导入是覆盖式，不留旧版本

## Constraints

- 上传按内容判定，不按扩展名（沿用 `homework` 能力已有的规则）；体积上限沿用同一套
  粗筛/精筛两道判断的模式，具体数值留给 design 阶段定（报告文件是纯文本，比 grades.csv
  小得多，不需要 2MB 那么大的上限）
- 需要一个字段标记"这条提交的 highlight/improve 是不是来自 report 导入"，
  否则 `_classify` 的整行覆盖逻辑无法区分要不要跳过这两列——具体实现（新增布尔列 vs
  其他方案）留给 design 阶段

## Success Criteria

- 讲师在详情面板给一个已交学员上传对应的 report.md，预览屏显示解析出的逐分项评语与
  亮点/改进建议；确认后详情面板的亮点/改进建议变成 report 里的版本，且新增一块
  显示逐分项评语
- 分项得分与已有 `scores` 不一致时，预览屏能看到警告，但确认按钮仍可点
- 讲师取消勾选某几项分项评语后确认导入，那几项的评语不写入，其余勾选的照常写入
- 上传过 report 的提交，之后重新导入这门课的 grades.csv，该提交的亮点/改进建议
  保持 report 版本不变；没上传过 report 的提交，重新导入照常更新

## User Stories

- 作为讲师，我批改工具产出的逐分项评语只在另一个仓库能看到，想在系统里直接看到
  这些细致点评，不用来回切换仓库
- 作为讲师，我担心重新导入 grades.csv 会把我刚上传的详细报告冲掉，希望系统保证不会

## Open Questions

- 逐分项评语具体存储形状（`HomeworkSubmission` 新增一个 jsonb 列 vs 独立表）留给
  design 阶段——两种都能满足需求，不影响这份需求的验收标准
- 上传体积上限的具体数值留给 design 阶段

## Referenced Capabilities

- `homework`（`openspec/specs/homework/spec.md`）—— 本变更修改「导入接口与调用方无关」
  与「排除名单让…」附近关于 `_classify` 整行覆盖的既有假设，新增一条"某些字段一旦被
  report 设置就不再被导入覆盖"的例外
