# homework-rubric Requirements

给每门课的作业分项配上满分，让作业页能显示「X / 满分」、分项条形图、总分按比例
着色的进度条——这三件事在 `homework` 能力落地时被明确推迟到这里。

## 为什么

`homework` spec 目前明确写着「系统 SHALL NOT 显示各分项的满分」，理由是满分不在
`grades.csv` 里（在另一个仓库的 `rubric.md`，而那两份文件对过错）。本项目规定不做
运行时跨仓库依赖，所以满分需要一个新的、应用内维护的数据源。有了这个数据源之后，
分项原本"只有原始分、看不出好不好"的展示就能补上参照系。

## Goals

- 课程页新增一处评分表维护入口：系统列出该课程已导入成绩里出现过的所有分项名，
  讲师逐项填一个满分数字（整数）
- 作业页分项展示改为「原始分 / 满分」；没配满分的项仍只显示原始分（不阻塞）
- 分项加一条按比例的条形图（有满分的项才有条形图）
- 总分显示一条进度条 + 三档颜色（≥90% 绿、70%–90% 黄、<70% 红）——**只有该课程全部
  分项都配了满分**才显示这条进度条，没配全时总分只显示数字，不显示进度条

## Non-Goals

- 不做分项名的手工输入——名字一律来自系统里已出现过的分项，避免打字错导致对不上
- 不做满分的批量导入（比如从另一个文件读入）——手动录入
- 不追溯改动历史（满分改了就是改了，不留版本）
- 不处理"同一门课分项名随时间变化"的特殊展示（评分表按分项名去重，跟哪一轮导入
  无关；旧分项名如果不再出现，评分表里那一条就是历史残留，暂不处理清理）

## Constraints

- 满分数据是应用内新表，不做跨仓库运行时依赖（`rubric.md` 那份文件对过错，不可信）
- 分项名的"去重列表"来自 `homework_submissions.scores` 里出现过的 `item` 值，
  不是一份预先定义的枚举——新增课程、新增分项都不需要改代码
- 总分进度条的"全部配齐"判定要按**当前**该课程用到的全部分项名（不是某一次导入
  的分项集合）——如果分项名随时间变过，新旧分项名都得配满分才显示总分进度条

## Success Criteria

- 讲师在课程页给某门课的所有分项配满分后，作业页详情面板的总分出现进度条与三档
  颜色，各分项出现「X / 满分」与条形图
- 只配了部分分项满分时，已配的项显示「X / 满分」+ 条形图，未配的项只显示 X，
  总分不显示进度条（只显示数字）
- 一门课都没配满分时，页面表现与本变更之前完全一致（回退到只显示原始分）

## User Stories

- 作为讲师，我想在课程页给这门课的评分项挨个填上满分，这样作业页就能看出
  "这个 11 分是接近满分还是刚及格"，而不只是一个孤立的数字
- 作为讲师，我一眼扫过总分的颜色就知道这批学员整体做得怎么样，不用逐条心算百分比

## Open Questions

- 满分数据在 API 层怎么附着到分项上（后端把 `max` 塞进每个 `ScoreItem`，还是前端
  单独拉一份评分表自己关联）——留给 design 阶段定，不影响这份需求的验收标准
- 满分是否需要设上限/下限校验（比如不能是负数、不能是 0）——留给 design 阶段，
  倾向至少拒绝负数和 0（满分为 0 没有意义）

## Referenced Capabilities

- `homework`（`openspec/specs/homework/spec.md`）—— 本变更取消其「不显示各分项满分」
  这条限制，需要在 propose 阶段对该 spec 做 MODIFIED
